# Critique — 规格启发式评审

对 PRD / 指标卡 / 数据字典做结构化评审，输出按严重度排序的缺口，不直接大改除非用户要求。

## 评分维度（每项 1–5）

| 维度 | 看什么 |
|---|---|
| 问题清晰度 | 用户与任务是否唯一 |
| 可验收性 | 有无失败用例与可观测指标 |
| 市场诚实度 | 大 A 约束是否落地 |
| 数据诚实度 | PIT、权威源、延迟 |
| 风控合规 | 红线是否点名 |
| 可建性 | 工程能否在依赖明确下开工 |
| 范围纪律 | Out of scope 是否硬 |

综合：列出 **P0 / P1 / P2** 问题；P0 = 未修不能进开发或不能宣称可上线。

## 常见 P0

- 主成功指标缺失或不可测
- 信号时点与下单时点矛盾
- 回测验收缺失却要求「上线」
- 对客话术越权且无合规路径
- 关键状态（涨跌停/停牌/延迟）未定义

## 输出格式

```markdown
# Critique: <target>

## Verdict
<一句话>

## Scores
...

## P0
- ...
## P1
- ...
## P2
- ...

## Suggested next command
`harden` / `metrics` / `backtest` / `distill` ...
```

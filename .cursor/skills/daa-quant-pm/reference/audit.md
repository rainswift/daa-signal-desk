# Audit — 规则 / 合规 / 可建性审查

比 `critique` 更偏「能否安全落地」的检查清单。针对目标文档或模块逐项给 Pass / Fail / N/A。

## 检查组

### A. 交易与市场规则

- T+1 仓位状态是否建模
- 涨跌停 / 停牌成交假设
- Universe 与板块规则是否点名
- 复权用途是否分离（展示 vs 回测）

### B. 研究诚信

- 未来函数
- 幸存者偏差
- 样本外与调参披露
- 成本与容量

### C. 风控

- 限额、禁池、集中度
- 熔断与人工介入
- 审计日志：谁在何时改了什么参数

### D. 合规表述

- 对内/对外文案分离
- 收益展示必要要素
- 适当性 / 权限（若对客）

### E. 工程可建性

- 数据依赖可获得
- SLO / 延迟可测
- 回滚与灰度
- 密钥与行情版权约束（若有）

## 输出

表格：`ID | 检查项 | 结果 | 证据 | 修复建议`。Fail 项给出建议后续命令（常为 `harden` / `clarify` / `backtest`）。
